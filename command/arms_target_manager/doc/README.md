## 这次重构做了什么

以前这个包有三套互不相干的目标发布路径：

- VR 直接发 `left_target` / `right_target`；
- RViz marker 自己也发同一批话题；
- 摇杆/键盘发速度流，还在 marker 里另算一份可视化。

于是只能靠几个开关和一个“1 秒冷却”让它们勉强错开。

现在整个包围绕四个可以独立扩展的面重写：

| 面 | 解决的问题 | 代码位置 |
|---|---|---|
| 信息输入 | 所有设备数据先汇到一处，映射不再依赖回调顺序 | `core/InputHub.h` |
| 语义 | 设备上报的编号 → 用户想做的动作 | `core/Action.h` |
| 会话 | 当前模式允许哪些动作、独占哪些目标 | `core/ModeRegistry.h` |
| 输出 | 谁在写目标、怎么写、怎么显示 | `core/ChannelOwnership.h`、`core/PoseTargetSink.h`、`core/TargetRouter.h` |

另外：

- 普通 VR 与全身 VR 合并成一个类 `VRInputHandler`，不再有两套状态和二十个回调；
- 手部命令只有一条出口 `HandCommandBus`；
- 与 ROS 无关的算法（冻结追赶、低通、姿态分解）单独放在 `detail/`，可以脱离节点测试。

## 还没做的部分

- 输入还没有统一成“按固定节奏统一计算”的 tick 模型（现在是回调触发）；
- 模式注册表只用于“允许哪些动作”，还没有做到“注册即接入”的插件式加载；
- 跨进程新增输入仍建议直接发既有目标话题，不经过所有权管理。
