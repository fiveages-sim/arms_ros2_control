# 整体结构

## 目录怎么分

```
include/arms_target_manager/
  ArmsTargetManager.h        对外门面：marker、菜单、状态判断
  ControlInputHandler.h      摇杆/键盘输入适配
  MarkerFactory.h            marker 外形
  core/                      四个可扩展面（与具体设备无关）
    TeleopTypes.h            基本词汇：哪一侧、哪个目标、哪个来源、优先级、提交、结果
    Action.h                 动作定义与“编号→动作”的绑定表
    ModeRegistry.h           模式声明：允许哪些动作、独占哪些目标
    InputHub.h               所有输入数据的汇聚与新鲜度查询
    ChannelOwnership.h       控制权：谁在写、还能写多久
    PoseTargetSink.h         一个目标的发送、显示、平滑
    TargetRouter.h           把上面几块串起来
    HandCommandBus.h         手部命令唯一出口
  detail/                    与 ROS 无关的纯计算
    PoseFilters.h            冻结追赶、低通、姿态分解
  VRInputHandler.h           VR 遥操作的唯一类（普通 + 全身）
  marker/                    三个 marker 的显示实现
src/
  ArmsTargetManager.cpp      门面实现
  ControlInputHandler.cpp
  MarkerFactory.cpp
  core/                      core 的实现
  detail/PoseFilters.cpp
  VRInputHandler.cpp         VR 遥操作全部实现（单文件，内部分 11 个区）
  marker/
```

`VRInputHandler.cpp` 是单文件，但内部按“做事的顺序”分成 11 个区，
文件开头有分区目录与组合键一览：

```
1 构造/生命周期    2 按键与组合键分发    3 手柄/头显/摇杆输入
4 普通模式映射     5 夹爪与手部命令      6 光学 R0 握手
7 WBC 门控         8 底盘与腰部          9 全身模式开关与骨架输入
10 全身映射与锚定  11 模式查询与共享工具
```

新增组合键只改第 2 区的入口附近，其余分区不用动。

## 一次目标下发经过哪些步骤

以“在 RViz 里拖动左臂 marker”为例：

1. RViz 把鼠标事件发给节点。
2. `ArmsTargetManager::handleMarkerFeedback` 把鼠标位置换算到 marker 坐标系，
   组装一个提交（`Intent`）：哪个目标、谁提交、优先级、占多久、要不要真的发。
3. `TargetRouter::submit` 先做坐标系换算，再向 `ChannelOwnership` 申请控制权。
4. 申请被拒绝：返回原因（例如 `manual_override`），调用方打一条限频日志，结束。
5. 申请通过：`PoseTargetSink` 记录目标、按需要做冻结追赶平滑和交接过渡，
   然后发布话题，并把目标换算回 marker 坐标系交给显示回调。
6. 控制器把实际接受的目标发回 `left_current_target`，
   由 `PoseTargetSink` 记录；如果不在“刚拖过”的抑制期，就刷新 marker 显示。
7. 松手后 500 毫秒没有新拖动，控制权自动到期；
   VR 下一次提交被接受，并用 400 毫秒从拖动终点过渡到 VR 目标。

## 三块代码各自的边界

| 层 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 适配层（`ControlInputHandler`、`VRInputHandler`、marker 反馈） | 读设备、算目标、提交 | 直接发目标话题 |
| core | 仲裁、换算、发布、显示、缓存 | 了解“VR/全身”这类业务概念 |
| detail | 纯数学 | 访问 ROS、访问节点状态 |

## 为什么这样分

- **加输入**：适配层多一个提交方，core 不动。
- **加目标**：core 里加一个通道，适配层填数据。
- **加模式**：`core/ModeRegistry.h` 加一条声明，动作处理只有一份。
- **加按键**：`core/Action.h` 加一条绑定，不用改模式判断。

这些在 [05-扩展方法.md](05-扩展方法.md) 里有具体步骤。
