# 现象与排查

## 先看日志

拖动被拒绝时会打印：

```
左臂拖动未生效：manual_override
```

VR 目标被拒绝时是调试级别日志，需要把日志级别调到 debug 才能看到。
常见原因见下表。

目标通道的控制权、拒绝原因不打印状态日志（拖动时会刷屏）。
需要时调 `router()->status()` 取 `TeleopStatus`；拖动被拒时仍会有
`拖动未生效：<原因>` 的限频 WARN。

## 常见现象

| 现象 | 可能原因 | 怎么确认 | 处理 |
|---|---|---|---|
| 机械臂完全不动 | FSM 不在 OCS2；控制拓扑不对；目标被别的来源占着 | 看 `fsm_state`（真实状态）与 `ocs2_wbc_controller/current_state`（WBC 模式）；看日志里的拒绝原因 | 切到 OCS2；确认全身/双臂控制器状态 |
| RViz 拖动没反应 | 当前是单次发送模式 | 看 marker 是不是方块（单次）还是球（连续） | 点“发送目标”，或切到连续发送 |
| RViz 拖动没反应 | 被更高优先级占用（理论上不会，拖动本身是最高） | 日志 `busy` | 通常说明同一目标被程序调用占着，等 500 毫秒 |
| 拖动时 marker 被拉回 | 已经超过 1 秒没有拖动事件 | 观察是否每次都要“追着拖” | 正常现象，1 秒内不会被拉回 |
| 松手 1 秒后 marker 跳一下 | 回显抑制到期，显示控制器实际目标 | 对比拖动位置和实际目标 | 正常现象；需要更快可调小 `echo_hold_after_manual` |
| VR 和拖动摇摆/抽动 | 说明还有第二条发布路径在发同一个话题 | `ros2 topic info left_target` 看发布者数量 | 应该只有本节点一个；若外部节点也在发，需要合并到同一处 |
| 摇杆推了没反应 | VR 或拖动正在控制这条手臂 | 看日志“当前由其它方式控制” | 正常；退出 VR 更新或等拖动结束 |
| 摇杆反应变小或抖 | 旧版本会与 VR 目标互相覆盖 | — | 本版本已改为互斥，不应再出现 |
| 胸部 marker 拖不动 | 旧版本全身跟踪每帧覆盖 | — | 本版本已改；若仍出现，检查是否有外部节点直接发 `body_target` |
| 头部拖动被忽略 | 旧版本 VR 控制时直接 return | — | 本版本已改为临时接管；若仍被忽略，看日志拒绝原因 |
| VR 目标下发被拒 | 有人正在拖 marker | 日志 `manual_override` | 松手 500 毫秒后自动恢复 |
| VR 恢复时跳变 | 恢复基准没有重建 | 日志是否有“从手动拖动恢复” | 相对映射会重建；全身模式会重新布置渐入 |
| 开始跟踪时目标点从别处飞过来 | 渐入锚点取到了上一次下发的旧目标（带底盘时可能已离开机器人） | 日志 `接管渐入已布置（锚点=...）` 与 `current_pose` 是否在发布 | 现版本锚点取实测位姿：确认 `left/right/body/head_current_pose` 有数据；实测缺失时会退回最后下发目标 |
| 目标报 `no_tf` | 输入和输出坐标系之间没有变换 | `ros2 run tf2_ros tf2_echo <源> <目标>` | 等 TF，或检查 `control_base_frame` / `marker_fixed_frame` 配置 |
| 目标报 `no_publisher` | 单臂模式下给右臂发目标 | 看 `dual_arm_mode` 参数 | 正常；单臂模式没有右臂发布器 |
| 双臂发送失败 | 左右臂还没有最近一次目标 | 日志“双臂目标尚未生成” | 先让每侧至少发过一次目标 |
| 机器人跟随的目标和 marker 不一致 | marker 处于 1 秒回显抑制中 | 等 1 秒 | 正常；或检查是不是有第二条发布路径 |

## 关于“回显”的两个时间

容易混淆的是两个不同的时间：

1. **控制权时长**（默认 500 毫秒）
   拖动结束后多久交还给别人。影响的是“谁在发目标”。

2. **回显抑制**（默认 1000 毫秒）
   拖动结束后多久内不把控制器回传的目标画到 marker 上。影响的是“看到什么”。

两者独立。改一个不会自动改另一个。

## 如果怀疑还有旧路径

用下面两条命令确认目标话题只有一个发布者：

```
ros2 topic info /left_target
ros2 topic info /body_target
```

正常情况下发布者数量都是 1，且节点名是 `arms_target_manager_node`。

如果看到别的节点也在发，说明有外部代码绕过了本模块，
需要把那部分也改成提交目标，或者停掉它。
