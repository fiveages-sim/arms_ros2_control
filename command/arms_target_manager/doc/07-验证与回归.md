# 验证与回归

## 编译

```
cd ~/fa_w2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select arms_controller_common arms_target_manager \
  --allow-overriding arms_controller_common arms_target_manager
```

`arms_controller_common` 和 `arms_target_manager` 在 `/opt/ros/jazzy` 里也有安装，
所以必须带 `--allow-overriding`。

## 启动冒烟

没有机器人时也可以确认节点能正常初始化：

```
source install/setup.bash
ros2 run arms_target_manager arms_target_manager_node --ros-args \
  -p enable_vr:=true -p dual_arm_mode:=true \
  -p control_base_frame:=world -p marker_fixed_frame:=base_link
```

应该能看到：

- `TargetRouter 已启动：control=world, marker=base_link, dual_arm=true`
- `ArmsTargetManager initialized`
- `VRInputHandler created（普通 + 全身同一份状态）`
- `全身模式已就绪：订阅 /teleop/body_*`

启动几秒后退出不应报错。

## 话题检查

启动后确认目标话题只有一个发布者：

```
ros2 topic info /left_target
ros2 topic info /right_target
ros2 topic info /head_target
ros2 topic info /body_target
ros2 topic info /dual_target/stamped
```

每个都应该是 1 个发布者（单臂模式下没有右臂和双臂话题）。

## 手动回归清单

有机器人或仿真时，按下面的顺序过一遍。

### 普通 VR

1. 进入 OCS2，按右摇杆进入更新模式。
2. 移动左手柄，左臂应跟随。
3. 按左 Y 暂停，左臂应停住；再按左 Y 恢复，应平滑继续，不跳。
4. 切换镜像，左右手应互换控制对象，夹爪镜像也应同步。
5. 摇杆微调应能叠加位移和旋转。

### RViz 拖动

1. 连续发送模式下拖动左臂 marker：
   - 机械臂应跟到拖动位置；
   - 拖动期间 VR 不应和它抢；
   - marker 不应被回显拉走。
2. 松手后 500 毫秒，VR 应重新接管；
3. 过渡应是平滑的，不应瞬间跳过去；
4. 松手 1 秒后，marker 应显示控制器实际目标。

### 单次发送

1. 切到单次发送；
2. 拖动 marker，机械臂不应动；
3. 点“发送目标”，机械臂应移动一次；
4. 发送的位置应是刚才拖到的位置，不是 VR 的目标。

### 胸部

1. 进入 OCS2 且身体模式为“跟随”；
2. 拖动胸部 marker，应能接管；
3. 全身跟踪开启时，拖动不应再被每帧覆盖；
4. VR 恢复时胸部目标应平滑过渡。

### 头部

1. 头部跟踪开启时，头部 marker 应可六自由度拖动（位置与姿态都能拖）；
2. 拖动位置，机器人头部应跟到拖动位置；
3. 松手后 VR 应重新接管，且不跳变；
4. 不再出现“拖动完全没反应也没有提示”的情况。

### 摇杆 / 键盘

1. VR 未控制时，推摇杆应发速度，机械臂应动；
2. VR 控制期间，推摇杆不应改变目标，日志应有“当前由其它方式控制”；
3. 松开 VR 后摇杆应恢复。

### 双臂

1. 双臂耦合时拖动一侧，另一侧 marker 应跟随显示；
2. 点“发送目标”应发出一条 `dual_target/stamped`，包含两到三个目标；
3. 尺度校准完成后应能发出一次双臂目标。

## 这次修改带来的行为变化

需要提前知道，避免误判为回归：

1. **胸部回显恢复**：全身跟踪期间，胸部 marker 现在会显示控制器实际目标，
   以前因为每帧刷新冷却而一直不显示。
2. **头部拖动不再被静默忽略**：现在会临时接管，松手后交还；
   头部保持原有的六自由度语义（位置与姿态都可下发）。
3. **摇杆速度流与 VR 互斥**：VR 控制期间摇杆不再发速度，以前是两路同时发。
4. **`dual_target/stamped` 只剩一个发布者**：以前 ATM 和 VR 各有一个。
5. **单次模式下拖动会记录预览目标**：菜单发送用的是拖到的位置。
6. **事件 26 在全身模式下也可用**：以前只在普通模式生效，但启动日志和文档都写了它。
7. **新增 1 Hz 状态日志**：目标通道的控制来源、是否有效、最近拒绝原因。
8. **按键判断改为“动作 + 模式允许集”**：行为不变，但被拒绝时会说明是哪个动作、哪种模式。

## 还没覆盖的部分

要完整回归，还需要这些场景的实机或仿真验证：

- 全身模式下底盘锁定/解锁切换时目标是否连续；
- WBC 单臂禁用/启用后的基准重建；
- 光学 R0 握手（进入更新、单臂恢复）；
- 多机命名空间下的 TF 与话题；
- 示教/回放类新输入。

这些场景目前只能靠日志和人工观察，后续建议补一套脚本化的录制回放：
把输入事件和目标话题同时录下来，改动前后对比轨迹。
