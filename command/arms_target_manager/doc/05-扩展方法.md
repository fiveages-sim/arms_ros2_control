# 扩展方法

下面按“你可能要加什么”来写。每条都只列必须动的地方，其余部分不用碰。

## 加一个被控目标（例如肘部）

1. `core/TeleopTypes.h`：在 `Channel` 里加一项（放在 `Count` 前面）。
2. `core/ChannelOwnership.h`：无需改，数组大小自动跟随 `Count`。
3. `core/TargetRouter.cpp` 的 `start()` 里：
   - 创建连续和单次两个发布器；
   - 在 `kTopics` 里补上控制器回传的话题；
   - 如果它属于双臂，考虑是否加入双臂合成。
4. `ArmsTargetManager`：设置显示回调 `setView()`，需要显示就加一个 marker。
5. 产生目标的输入里填这个通道。

发布、回显、抢占、交接过渡都会自动复用。

## 加一个动作（按键）

1. `core/Action.h`：在 `Action` 里加一项，并在 `kDefaultBindings` 里加一行
   （编号、需要的修饰键、禁止的修饰键）。
2. `core/ModeRegistry.h`：把它加进相应模式的允许集合
   （`kCommonActions` / `kNormalActions` / `kWholeBodyActions`）。
3. 动作处理：`src/VRInputHandler.cpp` 第 2 区（按键与组合键分发）里加一个 case，
   或加一个处理函数再从 case 调用。编号到动作的翻译只发生在该区入口，
   处理函数请只接收动作，不要再判断编号。

不要在别处再写 `if (wholeBodyActive())` 判断模式——那是会话层的事。

## 加一个模式

例如“单臂遥操作”“手柄绝对映射”“示教回放”。

1. `core/ModeRegistry.h`：
   - `ModeId` 加一项；
   - 定义它的 `ActionMask`（允许哪些动作）和 `ChannelMask`（独占哪些目标）；
   - 在 `kModes` 里加一行；
   - 在 `VrSession::refresh()` 里加“什么时候进入这个模式”的判断。
2. 实现映射：产出和现有一样的 `Intent` 提交，不要动发布层。
3. 进入/退出时清理：`releaseAll(SourceId::Vr)`、清摇杆偏移与暂停状态、重置渐入。

动作处理不需要改，因为“允许性”已经由模式声明回答。

## 加一个信息输入

### 输入在别的进程

直接发已有话题即可，不需要改这个包：

- 绝对目标：`left_target`、`right_target`、`head_target`、`body_target`；
- 速度：`left_target/twist`、`right_target/twist`；
- 单次：对应的 `/stamped`。

代价是绕过了控制权管理，会和 VR 抢目标。需要参与优先级就用下一种方式。

### 输入在本包内

1. `core/TeleopTypes.h`：`SourceId` 加一项。
2. `core/InputHub.h`：如果它提供的是骨架/手柄这类数据，加一个采样字段；
   如果只是目标位姿，直接提交即可。
3. 组装 `Intent` 并 `submit()`：

```cpp
Intent intent;
intent.channel = Channel::ArmLeft;
intent.source = SourceId::MyDevice;
intent.priority = Priority::Normal;
intent.position = ...;
intent.orientation = ...;
intent.frame = "world";                 // 数据在哪个坐标系
intent.lease = std::chrono::milliseconds(300);
intent.publish = true;
target_manager_->router()->submit(intent);
```

持续提交就是持续续期；停止提交即自动交还。

## 加一个骨架关节

1. `core/InputHub.h`：`Joint` 里加一项。
2. 对应的回调里 `input_hub_.setJoint(Joint::Xxx, sample)`。
3. 如果它属于新的能力分组，在 `setJoint()` 里映射到相应 `InputCap`，
   并在 `fresh()` 里加判断。
4. 需要的映射里读 `input_hub_.joint(Joint::Xxx)`。

## 加一种手部命令

手部只有一条出口 `HandCommandBus`：

- `publishSwitch(controller, open)`；
- `publishPercent(controller, percent)`；
- `controllerFor(target)` / `controllerForSide(side)`。

新增来源请调用这三个方法，不要再自己 `create_publisher`。
VR 的“接管点”逻辑保留在 `VRInputHandler` 里，因为它需要记住夹爪位置和扳机状态。

## 调整优先级与手感

| 参数 | 位置 | 当前值 |
|---|---|---|
| 拖动一次占多久 | `ChannelPolicy::lease` | 500 毫秒 |
| 拖动后多久不接受回显 | `echo_hold_after_manual` | 1000 毫秒 |
| 交还给自动控制时的过渡 | `handover_ramp` | 400 毫秒 |
| 拖动优先级 | `Priority::High` | 30 |
| VR / 程序调用优先级 | `Priority::Normal` | 20 |

改这些不需要动业务代码。

## 几条不要做的事

1. 不要再直接发目标话题——控制权和回显会再次分裂。
2. 不要再用一个布尔量表示“某输入正在控制”，用 `canWrite()` 或 `setBlocked()`。
3. 不要在 marker 里写发布逻辑，它只负责显示和接收鼠标事件。
4. 不要让两个来源同时发同一个绝对目标；要叠加就叠加速度或增量，并且只在一处积分。
5. 不要在标注“纯计算”的 `detail/` 里访问 ROS 或节点状态。
