# 目标通道

## 有哪几个目标

| 目标 | 话题（连续） | 话题（单次） | 控制器回传 |
|---|---|---|---|
| 左臂 | `left_target` | `left_target/stamped` | `left_current_target` |
| 右臂 | `right_target` | `right_target/stamped` | `right_current_target` |
| 头部 | `head_target` | `head_target/stamped` | `head_current_target` |
| 胸部 | `body_target` | `body_target/stamped` | `body_current_target` |
| 底盘 | `base_target` | `base_target/stamped` | `base_current_target` |

### 头部：与手臂一样是六自由度

头部目标的位置和姿态都由本模块下发，RViz 的头部 marker 提供完整 6 自由度拖拽
（3 平移 + 3 旋转），拖动位置和姿态都会生效。

唯一需要注意的是：控制器把头部当成 6 维绝对目标，所以头部目标的位置是一个“绝对量”，
不会自己跟着躯干重算；躯干或底盘移动后若需要头部目标同步，应由来源重新下发。
VR 头显驱动的头部目标（普通模式）是“相对机器人头部基准”的小幅偏移，属于原有设计。

### 底盘：只有平面三自由度

底盘目标只有平面位姿（x、y、偏航），因此 RViz 的底盘 marker 只提供 x/y 平移和偏航旋转，
不提供 z 平移和横滚/俯仰手柄。目标按控制坐标系解释；移动底盘模型下该坐标系是 `world`。

底盘 marker 只在 **FSM=OCS2 且底盘处于跟随模式**时显示。锁定与随动模式没有显式位姿目标，
不会显示这个 marker；切回这两种模式时 marker 立即隐藏。

另外还有：

- `dual_target/stamped`：左右臂（以及可见时的胸部）合成一条路径，由菜单“发送双臂”或校准使用。
- `left_target/twist`、`right_target/twist`：摇杆/键盘的速度流，不是位姿。

## 两种发送方式

- **连续**：发裸 `Pose`，只有位置和姿态，没有坐标系字段。
  下游按控制坐标系（通常是 `world`）解释，适合持续跟踪。
- **单次**：发 `PoseStamped`，带坐标系和时间戳，适合“发送一次、让控制器自己插值过去”。

每个目标由 `PoseTargetSink` 持有一对发布器，具体用哪个由提交内容决定：

- 拖动 marker、VR 跟踪：连续；
- 菜单“发送目标”、尺度校准：单次。

## 两个坐标系，别混用

模块里有两个坐标系，用途不同：

1. **控制坐标系**（`control_base_frame`，默认 `world`）
   - 所有真正发给下游的目标都用这个系。
   - 下游 WBC 用模型的根坐标系解释它；移动底盘一般是 `world`，固定底盘是 `base_footprint` 一类。

2. **显示坐标系**（`marker_fixed_frame`，默认 `base_link` 或 `world`）
   - RViz 里 marker 画在这个系下。
   - 鼠标拖动得到的位置也先换算到这个系。

`TargetRouter` 负责两头换算：

- 收到输入时：从输入声明的坐标系换到控制坐标系；
- 通知显示时：从控制坐标系换回显示坐标系；
- 收到控制器回传时：从回传消息自带的坐标系换到显示坐标系。

换算失败（比如 TF 还没起来）时，这次提交会被拒绝，原因 `no_tf`，
不会拿一个坐标系不对的目标去控制机械臂。

## 回显：控制器说的和你想的不一定一样

控制器会把它实际接受的目标发回来（`*_current_target`）。
这个回传值可能和下发值不同，例如被限幅、被插值、或者还在运动途中。

`TargetRouter` 的处理：

- 收到回传就记下来，必要时用来刷新 marker 显示；
- 手动拖动之后的 1 秒内不刷新，避免把用户刚拖到的 marker 立刻拉走；
- VR 控制期间正常刷新，所以 marker 显示的是控制器实际目标，而不是 VR 的期望值。

这解决了以前的一个问题：全身遥操作每帧都改 marker 里的目标变量，
导致回显一直被压制，界面上看不到控制器实际把目标限到了哪里。

## 双臂合成

`dual_target/stamped` 现在只有一个发布者：`TargetRouter::publishDual()`。

它用“最近一次真正发出去”的左臂、右臂目标（以及可选的胸部目标）拼成一条路径，
坐标系统一为控制坐标系。

什么时候会发：

- RViz 菜单里点“发送双臂”；
- 双臂耦合时点任意一侧的“发送目标”；
- VR 尺度校准完成后。

单臂模式下不会创建这个发布器。

## 双臂耦合时的拖动

双臂耦合开着的时候，拖动左臂 marker，右臂 marker 会跟着做同样的相对运动
（这部分是显示层的效果，`followCoupledRightMarker`）。

真正发给控制器的只有被拖动的那一侧目标，另一侧由控制器自己的耦合约束处理，
这一点和改动前一致。
